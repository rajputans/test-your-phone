    HOW THE SIGNALS ARE COLLECTED

    Signals you can
    actually verify.

    DeviceFit checks the target using DNS lookups and a bounded HTTP HEAD request. If the server rejects HEAD, it retries with a bounded GET, reads only response headers, and closes the response. Redirect destinations are validated and connections are pinned to checked public addresses.

    This deployment does not run a browser. Core Web Vitals, screenshots, responsive behavior, accessibility and device fit are shown as unavailable—not guessed. If a page responds with HTTP 405, it means the server rejected the check method; it does not, by itself, mean the site is broken.

    LIMITATIONS & PRIVACY
    01

    No device testing

    No physical phones, tablets or laptops are tested. Device suitability and current product prices cannot be determined by this deployment.

    02

    Browsing safety is unknown

    Headers and TLS observations do not detect all threats, constitute penetration testing, or prove a site is safe or malware-free.

    03

    Minimal collection

    Only the submitted URL and check results are kept in process memory for up to one hour. Page content and cookie values are not stored.
